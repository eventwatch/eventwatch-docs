---
title: サイトの URL が変わったとき
description: WordPress のサイトを複製・移転して URL が変わったときに、EventWatch への送信を再開する確認の手順です。
---

サイトの URL が変わると、プラグインは EventWatch への送信を止めます。ステージング環境のようなサイトの複製から、掲載中の投稿が書き換わるのを防ぐためです。

`http` と `https` の違い、大文字と小文字の違い、末尾の `/` の違いでは止まりません。

## 確認する

管理者が「設定 › EventWatch」を開くと、「サイトの URL が変わったので、EventWatch への送信を止めています。」と、記録している URL と今の URL が出ます。選ぶまで何も送りません。

| ボタン | 選ぶとき | 結果 |
| --- | --- | --- |
| 複製です | 元のサイトが別に動いている（ステージングなど） | 別のサイトとして扱う。保存していた API キーと、送信の記録を消す。「送らない」の選択は残る |
| 移転しました | サイトの場所を移した | 同じサイトとして送信を再開する。送ってある公開中のイベントを送り直し、EventWatch に新しい URL を伝える |

「複製です」を選んだサイトからイベントを送るときは、そのサイト用に発行した API キーを入れ直してください。

## wp-config.php でキーを設定しているとき

`wp-config.php` のキーは画面から消せません。「複製です」を選んでも、そのキーでイベントを送り続けます。

複製から送りたくないときは、ボタンを選ばずに `wp-config.php` からキーを消してください。キーが無いあいだは何も送らず、この確認も出ません。後でこの複製にキーを入れると、確認がもう一度出ます。
